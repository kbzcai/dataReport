# 数据填报系统

系统分为四类角色：

| 角色 | 职责 |
| --- | --- |
| `REPORTER` | 按已启用模板进行手工填报或 Excel 导入，只能查看本人数据。 |
| `LEADER` | 查看全部数据、按模板/周期筛选，并可修订填报数据。 |
| `MAINTAINER` | 维护填报模板和字段定义。 |
| `ADMIN` | 维护用户、角色以及全部业务数据。 |

## 本地启动

1. 在本机 MySQL 3306 端口执行 `database/schema.sql`。脚本只会创建新的 `data_reporting` 数据库。
2. 设置 `DB_USERNAME`、`DB_PASSWORD`、长度至少 32 位的 `JWT_SECRET`、`BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD` 环境变量；本地敏感配置不会提交到仓库。
3. 启动后端：`mvn -f backend/pom.xml spring-boot:run -Dspring-boot.run.profiles=local`。
4. 启动前端：`npm --prefix frontend install`，然后执行 `npm --prefix frontend run dev`。

首次启动仅在提供 `BOOTSTRAP_ADMIN_*` 环境变量时初始化管理员账号。登录后请立即修改初始密码，并按需创建模板管理员、数据领导和填报人员账号。

## Excel 导入约定

模板导入支持单行、多行和合并单元格表头。填报 Excel 支持两种模式：指定一个模板时，文件中的非空 Sheet 按同一模板校验；选择“按工作表自动匹配多个模板”时，每个非空 Sheet 优先按 Sheet 名称匹配模板名称/编码，未命中再按表头唯一匹配不同模板，空 Sheet 自动跳过，匹配失败或产生歧义时会指出 Sheet 名称并拒绝整批导入。填报人员也可在页面按模板字段手工录入数据。

自动匹配模式会先预览非空 Sheet 的数量和导入顺序，展示系统建议的模板名称；用户可以按顺序手动调整每个 Sheet 的模板名称，确认后才提交导入。

模板维护支持 Excel 多 Sheet 批量新增模板：上传后会先显示 Sheet 数量、顺序和“只能有表头、不能有数据内容”的校验结果，维护人员按顺序填写模板名称，确认后一次性创建多个模板。系统启动时会自动保证“月度经营填报”和“年度经营填报”两个默认模板存在。

模板字段可在页面按行新增和删除；删除字段会同步从该模板关联的历史填报数据中移除对应字段。删除模板前会提示确认，确认后会同时清空该模板的全部填报数据。模板文件由系统按照当前字段实时生成，可直接下载。

填报数据外层按“模板 + 填报人”独立展示，点击某个人的“查看明细”后只加载该人的分页明细表。明细表一行对应 Excel 一行，支持每页 10/20/50 条、横向滚动字段、固定操作列，只有点击“修改”后该行才进入编辑状态。

## 填报任务（第一阶段）

高权限用户可将同一模板发布为多个独立任务，并设置频率、周期标识、开始时间、截止时间和填报对象。任务页支持选择多个启用的填报人员，并按“已提交人员 / 待填报人员”展示进度，同一人员提交多行数据只计为一人。未选择人员的历史任务保留为开放任务，进度显示为“未指定人员”。填报人员只会看到分配给自己的已发布任务；在手工填报或指定单模板 Excel 导入时选择任务，系统会自动锁定其关联模板，并将每一行填报记录关联到该任务。对非高权限用户，后端会校验任务已发布、处于填报时间范围且本人在分配范围内；高权限用户仍可在任务结束后查看和修订数据。

任务必须依次经历“草稿 -> 已发布 -> 已关闭”。已有填报数据的任务不能更换关联模板或删除，以保留历史数据语义。

多 Sheet 自动匹配导入保持独立 Sheet 对应独立模板的规则，当前不绑定单一填报任务。

## 模板版本与任务明细

模板每次保存字段定义都会新增不可变版本，已有填报记录继续使用创建时绑定的版本校验和展示；新建任务默认固定到当前版本，也可以在任务页面选择历史版本。已有填报记录的任务不能再切换模板版本，避免历史数据与任务字段不一致。

任务发布到指定填报人员后，系统会创建“任务 + 填报人 + 模板版本”的独立任务明细；填报人提交首行数据后，对应明细状态会变为已提交。记录数据仍保留 `data_json` 以支持动态模板，同时同步写入 `report_record_value` 字段值索引表，后端提供 `GET /api/reports/query?fieldKey=...&value=...` 的精确字段检索接口。

模板字段可配置默认值、最大长度、数值范围、小数位数、正则表达式、下拉/多选选项、唯一性标记、可搜索、可汇总、列表显示、冻结列和是否允许导入。后端统一执行必填、默认值、文本长度、数字/金额范围与精度、日期/月/年、正则及选项校验；标记唯一的非空字段在同一模板内不得重复，并由数据库唯一索引兜底并发写入。禁用导入的字段不会要求 Excel 表头，必须由默认值补齐，且必填字段没有默认值时不允许保存该模板。模板生命周期支持草稿、校验中、已发布、使用中和已停用；已停用模板不能继续填报。

## 修改申请与审批

填报人员可以在“我的填报”中查看自己的分页数据。草稿记录可直接修改；已经提交的记录不能直接覆盖或删除，必须填写修改原因并提交完整行数据作为修改申请。申请处于待审批状态时，原填报数据保持不变，同一条记录不能重复提交待审批申请，申请人可自行撤回。

领导和管理员在“修改审批”中处理待办。通过时系统会比较申请提交时的记录版本与当前版本；若记录已经被其他人修改，审批会返回冲突，避免旧申请覆盖新数据。驳回必须填写意见。管理员删除填报记录时会同步清理该记录的申请历史，页面删除操作仍要求确认。

## 任务提醒与统计

填报人员可在“填报提醒”查看自己尚未完成的已发布任务：截止时间已过显示“已逾期”，三天内截止显示“即将截止”，其他未提交任务显示“待填报”。任务可单独设置“允许逾期填报”；未启用时，填报人过期后无法新增或提交数据，管理人员仍可维护。提醒按当前任务状态、截止时间和提交记录实时计算，提交后自动消失，不依赖邮件、短信或定时写库。

管理端可通过任务接口获得全部任务、已发布任务、即将截止任务、逾期任务、已完成任务和待填报人员数的汇总；任务列表仍保留逐任务、逐人员的提交进度。

## 数据质量校验

模板字段的必填、数字、日期和月份规则由后端统一校验，因此手工填报、批量手工提交、单模板导入和多 Sheet 导入的约束保持一致。数字字段允许千分位，日期必须为 `yyyy-MM-dd`，月份必须为 `yyyy-MM`。Excel 数据行校验失败时，错误信息会包含工作表名称和 Excel 行号，整批导入会回滚，不会留下部分成功的数据。

## 查询、导出与看板

管理端“数据看板”展示任务总数、已发布、即将截止、逾期和待填报人员统计，并保留任务逐行完成进度。导出功能可按模板和任务筛选，导出文件包含任务、填报人、状态、时间及模板字段，只有 `ADMIN` 和 `LEADER` 可以导出，数据范围遵循后端权限校验。

## 导入批次与操作日志

每次 Excel 导入都会生成导入批次，记录原始文件名、导入行数、失败行数、处理状态和摘要。填报页提供批次列表和失败错误 CSV 下载入口；失败时保留工作表、行号和错误信息，也可通过 `GET /api/reports/import-batches/{id}/errors/download` 下载。导入仍采用整批事务，出现错误时填报数据不会部分落库。

填报数据的新增、修改、删除、审核和修改申请通过操作日志留存前后 JSON、操作人、操作类型、原因和时间；填报人在“我的填报”中可以查看日志、退回意见并在退回后重新提交申请，也可通过 `GET /api/reports/{id}/change-logs` 查询。
